# Командная модель: OpenCode + Vibe Kanban + Cursor

Дата: 2026-03-31

## Роли

- **Vibe Kanban (диспетчер задач):** backlog, статусы, приоритеты, карточки, acceptance criteria, запуск workspace.
- **OpenCode (длинный исполнитель):** большие прогоны в терминале, многошаговые реализации, автономная работа по чёткому брифу.
- **Cursor (оркестратор + точечный исполнитель):** локальные правки в IDE, быстрые фиксы по lint/type, донастройка интеграций и финальная полировка.

## Единый протокол синхронизации

1. **Одна активная линия работы на задачу.**  
   Только один ведущий исполнитель (OpenCode или Cursor) делает основной проход.
2. **Источник правды по задаче — карточка в Vibe Kanban.**  
   В описании/комментариях фиксируются цель, ограничения, DoD.
3. **Handoff фиксируется в `MAIN_AGENT.md`.**  
   Минимум: ведущий, что сделано, что осталось, где смотреть.
4. **Передача в OpenCode — только с “пакетом”.**  
   Цель, контекст (пути), ограничения, критерии готовности, обязательные команды проверки.
5. **Финальная интеграция через Cursor.**  
   Проверка диффа, lint/type/tests, доведение до состояния merge-ready.

## Кто что делает по умолчанию

- **OpenCode берёт:**
  - задачи с длинным терминальным циклом;
  - крупные рефакторы и изменения в нескольких подсистемах;
  - сценарии, где нужно автономно “дойти до результата”.
- **Cursor берёт:**
  - правки в 1-5 файлов и быстрый цикл IDE;
  - устранение lint/type/test-регрессий;
  - ручную донастройку UI/интеграций и финальный QA перед завершением.
- **Vibe Kanban всегда:**
  - точка входа в задачу;
  - контроль статусов (`To do` -> `In progress` -> `In review` -> `Done`);
  - хранение acceptance checklist.

## Шаблон запуска задачи (коротко)

1. Создать карточку в Vibe Kanban: цель + acceptance checklist.
2. Выбрать ведущего:
   - длинный прогон -> OpenCode,
   - короткая IDE-задача -> Cursor.
3. Выполнить работу.
4. Синхронизировать `MAIN_AGENT.md`.
5. Закрыть карточку только после проверки критериев готовности.
