# Vibe Kanban: handoff-ready шаблон карточки

Используйте этот шаблон в описании issue или в первом комментарии.

---

## 1) Цель

Одно предложение: какой результат должен быть в конце задачи.

Пример:  
`Стабилизировать backend smoke-check и получить зелёные ruff/mypy без регрессий API.`

## 2) Контекст

- Репозиторий: `fastapi-project-backend`
- Ветка-основа: `main`
- Ключевые пути:
  - `src/sec_scanner/`
  - `tests/`
  - (добавьте нужные)
- Связанные материалы:
  - `MAIN_AGENT.md`
  - `AGENTS.md`
  - (добавьте docs/* при необходимости)

## 3) Ограничения

- Не менять публичный API без явного согласования.
- Не добавлять новые зависимости без необходимости.
- Не трогать несвязанные модули/файлы.
- Сначала минимальный фикс, потом рефактор (если нужен).

## 4) Роли и ведущий

- Ведущий исполнитель: `OpenCode` или `Cursor`
- Оркестратор: `Cursor`
- Трекер статуса: `Vibe Kanban`

## 5) Acceptance checklist (DoD)

- [ ] Изменения локализованы и соответствуют цели.
- [ ] `ruff check src/ tests/` проходит.
- [ ] `mypy src/` проходит.
- [ ] Ключевые тесты/сценарий задачи проходят.
- [ ] В отчёте указано, что именно изменено и как проверено.

## 6) Команды проверки

```bash
. .venv/bin/activate
ruff check src/ tests/
mypy src/
pytest -q
```

## 7) Формат результата от исполнителя

1. Что сделано (3-6 пунктов)
2. Какие файлы изменены
3. Результаты проверок (команды + итог)
4. Риски/что осталось
5. Рекомендованный следующий шаг

## 8) Handoff-блок в MAIN_AGENT.md

После передачи или завершения задачи добавить строку:

`YYYY-MM-DD — <кратко что сделано>, ведущий=<OpenCode|Cursor>, следующая точка=<что дальше>`

---
