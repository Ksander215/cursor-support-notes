## Письмо 1 — Welcome + доставка (T+0)

**Тема:** Ваш скан API готов — что смотреть в первую очередь  
**Превью:** Три вещи в отчёте, которые не стоит игнорировать перед релизом

**Текст:**

Привет, {{first_name}}.

Спасибо, что попробовали **sec-scanner.pro** — если вы уже запускали скан, отчёт как раз про то, что часто ломают в API: auth, доступ к объектам, лишние данные в ответе, rate limiting.

**Если коротко — что проверить первым:**
1. Критичные находки по auth / access control (если есть в отчёте).
2. Утечки данных в JSON (лишние поля, PII).
3. Заголовки и политика ошибок (не светить стек в проде).

Повторный прогон после фиксов — лучший способ убедиться, что проблема закрыта: [запустить скан снова](https://api.sec-scanner.pro).

Если удобнее в мессенджере — пишите в Telegram: {{telegram}}. Отвечу по конкретным строкам отчёта.

**Превью:** Минимальный чеклист без «безопасности на месяц»

**Текст:**

## Письмо 3 — Мягкий оффер аудита (T+5)

**Тема:** Когда автоматического скана мало: аудит API за фиксированный срок  
**Превью:** Express / Standard / Bundle — одна страница с ценами

**Текст:**

Привет, {{first_name}}.

Автоматический скан хорошо ловит типовые проблемы. Если перед **сдачей клиенту, аудитом или релизом** нужен человек, который приоритизирует находки и даёт понятный план фиксов — это как раз платные аудиты на одной витрине: {{audit_url}}

Кратко по форматам:
- **Express** — быстрый разбор + приоритеты.
- **Standard** — глубже, с расширенным отчётом.
- **Bundle** — аудит + материалы под CI/CD, если хотите закрепить процесс.

Можно начать с вопроса в Telegram {{telegram}}: опишите API (staging, auth), и подскажу, какой формат ближе.
